
1.1.What the shebang line means:

The shebang (#!) is a special instruction at the very top of a script that tells the operating system which "interpreter" to use to read the file.
By using #!/usr/bin/env python3,I am telling the system:"Don't try to run this as a generic shell script;instead,look through my computer's 
environment paths, find where Python 3 is installed, and use that to run this code." It makes the script "self-aware" of how it should be executed.

1.2.How I executed hello.py without using python:

I used the command chmod +x hello.py to modify the file's permissions, adding the "executable" bit.
This signals to the OS that the file is a program rather than just a text document.
Once the permission was set,I ran it using ./hello.py.
The ./ tells the terminal to look for the file in the current folder.
Because of the shebang line, the OS knew to automatically pass the file to Python without me having to type python3 explicitly.

2.1.Why Python runs "directly" vs. C requiring compilation:

Python is an interpreted language. When you run a Python script, another program (the interpreter) reads your code line-by-line and executes it immediately.
In contrast, C is a compiled language. A computer's CPU cannot understand C code directly; it only understands binary (1s and 0s).
Therefore, C requires a "compiler" to translate the entire source code into a standalone machine-code file before it can be executed.

2.2.Mention the difference between an interpreter and a compiler in your explanation:

  The difference between an Interpreter and a Compiler:

  1.Compiler (C): Translates the entire program into machine code all at once and saves it as an executable file.
                  This makes the final program run very fast, but you must re-compile every time you change the code.

  2.Interpreter (Python): Translates and executes the code on the fly, line-by-line.
                          This makes development faster and more flexible because you don't have to wait for a build step.
                          but it usually results in slower execution speed compared to compiled code.
